# ADHD project — 「まず5分」

ADHD傾向のある人が、**複数の重い課題を抱えていても、いま取りかかれる一歩を見つけられる**ためのアプリ。
タスク管理アプリではない。

## 支えたい二つの場面

1. 重要な課題が同時に頭に浮かび、着手する前に負担が大きくなる場面
2. 集中が途切れたときに、自分を責めてしまう場面

## 設計の軸

- **考える負担は減らす** — 分解・分類・計画づくりを本人に求めない
- **本人が変えられる余地は残す** — 提案が合わなければ調整できる
- **中断後も戻りやすくする** — 途中でやめても、次に戻れる

### 合否基準

- 初回に課題を預けた翌日、**アプリを開くだけで無理のない一歩に戻れるか**
- **AIが使えない日でも**、利用者に計画づくりを背負わせず、取りかかれる一歩にたどり着けるか
  (AIの有無で、アプリが引き受ける役割まで変わらない設計にする)

## 仕組み

### 一歩の生成(AIなしで成立する部分)

課題文から扱う対象の型を判定し、型ごとに用意した候補から一歩を出す。
判定できない場合だけ「手元に使うものはある?」と一問尋ねる。答えなくても一歩は出る。

型: 勉強 / 書類・文章 / 連絡 / 片付け / 手続き / 運動 / 判定不能時の汎用

### 「もっと小さく」の方向

進行方向ではなく、**その行動に必要な準備へ戻す**。

```
教材を開いて、前回の続きのページを見る
  → 教材を開く
    → 教材が置いてある場所を見る
      → 教材がどこにあるか思い出せるか、机の上を見る
```

「一行書く → 30秒だけ書く」のような時間の短縮は縮小ではない(何から始めるかが不明なまま)。

### AIの役割

一歩を**用意する責任はアプリが持つ**。AIは具体性を高めるためだけに使う。
AIが落ちても辞書の一歩がそのまま残り、本人に分解が返ることはない。

### 着手の記録

途中でやめても「着手」として残る。未完了数・期限切れ・連続日数・空白日は**実装しない**
(完璧主義の自責を誘発するため)。

## ファイル構成

```
ADHD project/
├── index.html                     アプリ本体(単一ファイル・7言語対応)
├── netlify.toml                   Netlify設定
├── netlify/functions/decompose.js AI中継(APIキーはサーバ側の環境変数)
└── README.md
```

## デプロイ

1. GitHubに上記構成のままアップロード
2. Netlifyでリポジトリを連携(ビルド設定は空欄)
3. Site configuration → Environment variables に `ANTHROPIC_API_KEY` を登録
4. **Trigger deploy で再デプロイ**(環境変数は追加だけでは反映されない)
5. アプリの「データの管理」→「AIの接続を確認」で疎通確認

費用: Netlifyは無料枠。Anthropic APIは従量課金で、1回の呼び出しが1円未満。
初回にプリペイドクレジット($5〜)の購入が必要。

利用開始時は**ホーム画面に追加**すること(iOSのlocalStorage 7日ルール対策)。

## 現状(v12)

### 確認済み(AI無効の状態で検証)

- 課題を預けると即座に一歩が出る
- 「もっと小さく」が準備側へ戻り、最小で止まって伝える
- 「別のことにする」が回数制限なしで切り替わる
- 判定できない課題でも、答えなくても一歩が出る(行き止まりなし)
- 課題を切り替えてから中断しても、翌日は最後に触った一歩に戻る(v12で修正)

### 未解決

1. **入口が二つあり、負担の扱いが割れている**
   「預ける」経路は一歩まで自動、「書き出す」経路は分解と割り当てを求める。
   統合するか判断待ち。

2. **多言語の訳が未検証**
   7言語は機械的に用意したもので、ネイティブチェックを通していない。
   日本語話者に配る限りは影響しない。

### 検証時に見るべきこと

画面が動くかではなく、以下で負担が増えていないか。

- 提案が外れたとき
- 「もっと小さく」を繰り返したとき
- 中断して翌日戻ったとき
